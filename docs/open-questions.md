# Open questions

Known gaps and behaviours that may surprise, left open on purpose. Remove an
entry when a phase settles it; add one when a phase leaves something open.

- go.dev declares no code languages. RoNote still never guesses one; the user can choose, per block or for all unlabelled code at once.
- Link status is resolved when a document opens and again after an import finishes. A page imported from another tab shows as not imported until then, and following it opens the existing document.
- Following a link that fails leaves its message under the link until the next link is followed.
- After macOS sleeps, the podman VM's clock can lag for a few minutes. Jobs no longer wait on it (P12), but tests that compare a database time with the app's, such as a user's `created_at` "about now", still fail meanwhile. `make doctor` says so and prints the fix.
- Code in a runner worker can post a false "done", which stops its run's clock while it keeps running. The next run then waits behind it and is interrupted at its own limit, so the waste lasts until the reader runs something or leaves.
- Safari isn't cross-origin isolated (no COEP `credentialless`), so Stop there ends the session; the e2e tests run Chromium only, so that path is covered by unit tests alone.
- In dev, open the app at `127.0.0.1:5173`: the runner answers only `RONOTE_PUBLIC_URL`'s origin. At `localhost:5173` the app still loads, and a Run says the code runner didn't answer.
- JavaScript blocks are read on their own: one that uses a name another block imports (VitePress's `postcssIsolateStyles({...})`) offers Run, and fails with a `ReferenceError`.
- A JavaScript `setInterval` never cleared keeps its run going until Stop or the 30 s limit, as a Node script would. Output Python prints after its run has ended (from an asyncio task) is dropped.
- doctest ends an example's expected output at a blank line, so output a page shows with blank lines (the tutorial's `__doc__` example) fails without `<BLANKLINE>`. Version differences other than an exception's wording, such as Python 3.14's annotation order, are failures.
- The runner's Vite build warns that Pyodide's Node-only imports are left out; that is expected.
- Highlights go in prose the editor edits, and in code; not in table cells, captions, or prose inside tabs, which are drawn read-only.
- Jump to puts the caret at a highlight's start rather than selecting it, so the toolbar does not offer to highlight it again.
- A highlight's note is plain text; links and formatting in notes are for later.
- A user's document keeps the IR it was made from; re-importing returns it. Syncing to a newer snapshot will have to merge user blocks and edits, and DocContent keeps what that needs.
- A deleted source block can only come back by undo in the same session; there is no "restore from source" for missing blocks yet.
- Images inside source blocks are locked like code, tables and tabs, a step beyond the P10 brief, because the editor shows them as atoms.
- The "edited" label sits above the block, not in the notes margin, which annotations (P12+) will use.
- The fetch rate limit is per worker process; more than one worker process needs a shared limit.
- Pages of a recognised framework in another layout, such as a Docusaurus blog post, fall back to generic with `adapter_fallback`.
- A failed or lost import is shown until dismissed, but only in the session that started it.
- The URL length check counts characters in the browser and bytes on the server.
- Jobs: the outbox and relay a non-Postgres broker needs are specified in ADR 0009, not built. `internal/events` still needs Postgres LISTEN/NOTIFY; ADR 0009 says what a swap would take.
- River deletes completed jobs after 24 h, so after that an import's Key could be enqueued again. The handler does nothing for a finished import, and only a new import makes a job, so nothing re-runs.
- Jobs queued in River's old args shape (`{import_id, owner_id}`, before P14) don't read in the new one and are cancelled. Only local databases hold any.
- `memjobs` times retries on its clock but attempts' timeouts on the wall clock.
- Rate limits count in memory per API process: a second API process needs a shared store first.
- A rate-limited sign-in (`/api/v1/auth/github/*`) answers the JSON envelope to a browser navigation; a person sees raw JSON. Rare at 20 a minute per IP.
- An import job already queued when its user deletes the account ends as permanent (its import is gone) and logs at error level.
- The e2e users file holds 16 worker users; more Playwright workers than that fail at sign-in with a message saying so.
- Search: queries with no answer score a best cosine similarity of up to 0.60, and answerable ones as low as 0.29, so no threshold can say "I don't know". P17 leaves it to the model, told to say so. On the real model (`testdata/retrieval/chat-report.md`) it refused no answerable question, and of the 8 unanswerable ones 4 called `not_in_library`, 3 said so in text with no citation (shown as "No sources") and n04 answered with 2 citations, a refusal in its words that cites the FastAPI setup. The prompt says to call the tool; Haiku 5.5 does not always.
- Chat: which answers are being written is known per API process, so Stop reaches only answers its process started; a second API process needs a shared signal first, as the rate limits need a shared store. One answer per conversation holds across processes: it is checked in Postgres.
- Chat: its hit rate is 0.96 by section and 0.68 strict (an expected block itself), search's recall@10 being 0.96. Section misses (3): e06 unsourced, e08 right but under the `init` section rather than Panic, p16 right but citing the parent of the expected section; a parent of an expected section is not a hit, only a subsection is.
- Chat: once in 86 asks (e06) the model wrote markers like `([1-6])` and no citation came; it shows as "No sources" with its text, and asked 5 more times e06 cited every time.
- Chat: the panel lists the 30 latest conversations, with no paging yet.
- Chat: a citation chip focused while its answer streams loses focus when the saved answer replaces the streamed one.
- Chat answers in one model's words; Haiku 5.5 may think within its 1,024 output tokens at effort low, which could cut a long answer short (`max_tokens`). All 80 of the chat eval's answers finished.
- Search: one chunk over Ollama's 4096-token context fails its whole document's index job for good (ADR 0011), so that document isn't searchable at all; the chunker's 6,000-character cap keeps text over about 1.5 characters a token within it. Skipping, or splitting, the one chunk would be finer.
- Search: identifiers, errors and how-to questions are at recall@10 1.0 on the eval; paraphrases (0.85) and questions across two documents (0.90) are where it misses. The eval's 80 queries were written by the agent; 20 are marked for review.
- The fake embedder (`cmd/fakeembed`) matches by shared words, so end-to-end tests check the plumbing of search by meaning, not its quality; `make eval` checks that.
- A search result lands on its chunk's first block; a result whose words are further into the chunk lands a little above them.
- Effective Go never names `ServeMux`: searching it finds `ServeHTTP` and `HandlerFunc` code by meaning, not an exact match.
- PDFs: scans need OCR (later phase). docling's figures are dropped and counted; a figure that is a picture of code drawn as an image (not text) is lost.
- PDFs: docling normalizes prose: curly quotes made straight, a space now and then before punctuation (`print _ n` for `print_n`). Code is read from the text layer and keeps neither change; prose has no such reader yet.
- PDFs: a document set wholly in a monospace font would map to code throughout; no fixture is.
- PDFs: slides lay notes over code; where they share a box, the note comes out among the code's lines (MIT 6.0001 lecture 3).
- PDFs: code language comes from the picker; docling's code enrichment would guess it with a model, at CPU cost, and its text would be generated. Off.
- PDFs: conversion takes about 1.87 s a page on GitHub's arm64 runner, hence the 100-page cap (ADR 0013). A longer book could be converted in page ranges, each a docling task within the timeout, and joined; not built.
- PDFs: an OOM-killed docling answers like a dropped connection, so the import retries it as a network error, three attempts in all, rather than failing it as too large.
- Chat: a turn that ends with no text and no tool call (Haiku 5.5 once did, with its tools turned off, which the last call no longer does) is saved as unsourced and shows "No sources" with nothing above it.
- Production (ADR 0014, ADR 0015): the weekly ARM job proves docling at the 100-page cap, Ollama in its 2 GiB, the model pull and its digest check, and the backups and the drill, on GitHub's arm64 runner. Still unproven until the real host: pasta keeping clients' addresses (the smoke suite connects from the host itself), Let's Encrypt certificates (Caddy issues its own for `.test`), and docling's speed on the A1's Altra cores (docs/runbook.md checks all three).
- Chat's daily spending cap counts answers when they finish, so answers already being written can take a day past it by what they cost (a few tenths of a cent each).
- The smoke suite signs in as `RONOTE_ENV=test` (staging and prod refuse the fake sign-in), so it never sees `__Host-` cookies; `check-config` and config's tests cover them.
- Go-live (docs/runbook.md): the host pulls the release's images from ghcr.io anonymously, so `ronote-api`, `ronote-worker` and `ronote-web` must be public packages; the alternative is a read-only token as a podman login on the host. Not decided.
- Go-live: rotating the Postgres password and the restic password are commands in the runbook, not a script; `install.sh` only makes secrets that are missing. Old releases' images are removed by hand when the disk alert says so.
- Go-live: the runner's Pages site and the host's release roll back separately: `ronote-deploy` doesn't touch Pages.
- The query embedder reads `ronote-ollama`'s volume read-only, which Ollama 0.40.16 serves once a writable instance has laid it out. An Ollama bump that changes that layout reaches `ronote-ollama-query` only after `ronote-ollama` has migrated it, and if it can't serve the old layout read-only, it fails its health check until then.
- Ollama's `/api/tags` digest for a model can change when 0.40.16 migrates a model pulled by an older Ollama (`manifests-v2`): a copy reported `d84267e5df12` for the files a fresh pull reports as `ac6da0dfba84`, the pin `install.sh` checks. A host whose model came from an older Ollama could fail that check after upgrading.
- `ronote-ollama-query`'s 1.5 GB limit is an estimate (ADR 0014) until the weekly ARM job measures its peak.
