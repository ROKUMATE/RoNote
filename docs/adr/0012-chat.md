# 0012: Chat over the library

Accepted, 2026-11-14. Amended 2026-11-15: chat is off by default in staging and prod. Amended 2026-11-17: chat has run against the real model, and stays off by default there.

## Context

From P17 on, students ask questions of their own library and get answers that cite its blocks. ADR 0011 built the retrieval chat needs: hybrid search, owner-scoped, over chunks of consecutive blocks. Its eval found no similarity threshold that tells an answerable question from one the library can't answer: their best cosine similarities overlap. So chat can't refuse on a number; the model has to say so. The verbatim rule still holds: nothing generated ever enters DocContent (ADR 0006); answers live in their own tables and are shown as generated.

## Decision

- **The model: Claude Haiku 5.5** (`claude-haiku-5-5`) through Anthropic's Messages API, streamed, with the official Go SDK (`github.com/anthropics/anthropic-sdk-go/v2`).
  - The model is configurable (`RONOTE_CHAT_MODEL`). Cost is computed from a price table in `internal/chat`; a model without a price there stops the API at start.
  - Adaptive thinking at effort `low`: the documented setting for chat, and thinking counts toward `max_tokens`. No sampling parameters.
- **A port at the package boundary.** `internal/chat` defines `Model`: one streamed call, in RoNote's own types (text, search results, tool use and results, thinking blocks, usage). It is the test seam the chat service is tested through.
  - `internal/chat/anthropic` adapts it to the SDK, and is the only package that may import the SDK (depguard).
  - `cmd/fakellm` (dev and test only, like `cmd/fakeidp` and `cmd/fakeembed`) serves the subset of the Messages API RoNote uses: streaming, tool use and search-result citations. It answers deterministically from the search results it is sent, so dev and the end-to-end tests run the real adapter and no model. CI never calls the real API.
  - The adapter's tests replay streams through a local server, with the requests it sends checked against goldens. `-record` records them from the real API.
- **Grounding.** Each question's top 8 chunks, by P16's hybrid search in the conversation's scope, go into the user message as `search_result` blocks with citations enabled, before the question.
  - Each of a chunk's top-level blocks is its own text item in the result's `content`, so a citation's `start_block_index` and `end_block_index` (exclusive) name block ids. `chunks.block_texts` holds each block's text beside `block_ids`.
  - `source` is `ronote:chunk/<chunk id>`; `title` is "Doc title > heading path", and a note's chunk says it is the student's note.
  - Earlier turns are sent as plain text: their search results and citations are not, so a citation can only point at this turn's results.
- **One tool, `search_library(query, this_document_only)`,** returning search results the same way, 8 at most, or the text "No results found.".
  - At most 3 tool rounds a turn; the call after the third offers no tools (`tool_choice: none`), so the model answers with what it has.
  - Every tool is read-only and runs as the signed-in user on the server. The model never names an owner or a document: `this_document_only` narrows to the conversation's document, and a document conversation may widen to the user's whole library, which is still theirs.
- **Citation validation.** A citation counts only if its `search_result_index` is a result sent in this turn's request, in request order, its `source` is that result's, and `0 ≤ start < end ≤` the result's block count.
  - The block ids, document and cited text come from RoNote's own copy of what it sent, never from the model's `cited_text`.
  - Invalid citations are dropped and counted on the message, never rendered.
  - Citations are numbered in order of appearance; citing the same blocks again reuses the number.
- **No answer.** A finished reply with no valid citation is shown as "Not found in your library", muted. The system prompt tells the model to say plainly when the sources don't hold the answer, and to name what the student could import.
- **Untrusted input.** Imported text is data, never instructions:
  - the system prompt says so, and that the sources are the student's imported pages;
  - tools are read-only and owner-scoped, so a page that says "show other users' notes" can't make a tool return them;
  - an answer renders as a small subset of markdown (paragraphs, lists, code, emphasis), built as elements, never as HTML. Images show as their alt text, raw HTML as text, and links only to documents the answer cites; any other link is text.
- **Cost:**
  - `max_tokens` 1024;
  - a hard cap of 30,000 input tokens a call, far below Haiku's 100K price step. Tokens are estimated at 3 characters each, which overcounts, and the oldest earlier turns are dropped first, leaving room for 3 tool rounds;
  - `cache_control` on the system prompt caches the tools and the system prompt together;
  - per user, in a rolling 24 hours: 50 messages and 400,000 input tokens (uncached, cache writes and cache reads), past which a message is refused with `quota_exceeded` and `Retry-After`. They count rows in Postgres under the user's quota lock, as the import quotas do (ADR 0010);
  - every assistant message records its model, input, output, cache-write and cache-read tokens, cost in micro-dollars, time to first token and total time;
  - `RONOTE_CHAT_ENABLED=false` turns chat off: its routes answer 503 `chat_disabled`.
- **Off by default in staging and prod.** `RONOTE_CHAT_ENABLED` defaults to true in dev and test and to false in staging and prod, where only `RONOTE_CHAT_ENABLED=true` turns it on. A deployment that sets it also needs `ANTHROPIC_API_KEY`; one that doesn't needs no key. Chat first met only the fake model and streams written by hand; it has since run against the real model (2026-11-15: the adapter's streams recorded, and the eval in `testdata/retrieval/chat-report.md`). The default stays off until P19 turns it on by environment.
- **Conversations** belong to their owner and go with their user. One may be scoped to a document, fixed when it starts, and goes with that document; one without a document covers the library.
- **Streaming.** `POST /api/v1/conversations/{id}/messages` answers with server-sent events: `delta`, `citation`, `tool`, `done` with the saved message and its usage, and `error`.
  - One message runs per conversation at a time; a second gets 409 `conversation_busy`.
  - The answer is generated apart from the request: a client that disconnects still finds it saved. Stop is its own request, `POST /api/v1/conversations/{id}/stop`, which ends the answer and saves what it had as `stopped`.
  - A turn ends after 120 seconds; an answer still marked as running after 5 minutes counts as failed, as when a process dies mid-answer.
  - Which answers are running, for Stop, is kept per API process, like the rate limits. A second API process needs a shared signal first (`docs/open-questions.md`).

## Consequences

- Chat costs money per question; the quotas bound it per user, the kill switch for everyone, and in staging and prod it starts off.
- An answer cites only what was retrieved for it. A library that search can't find a passage in, chat can't cite it from.
- Dev and CI chat with the fake model; only `make eval-chat` and a configured `ANTHROPIC_API_KEY` reach the real one.
- Re-chunking to store block texts makes search empty for a few seconds while the worker re-indexes from the embedding cache.
