# Commands

Every make target and what it runs, in detail. AGENTS.md keeps one line each.

| `make eval-chat` | asks every query of `queries.jsonl` through the chat service, a conversation each over the whole corpus, of the real model (`RONOTE_ANTHROPIC_API_KEY`, `RONOTE_CHAT_MODEL`; docs/adr/0012-chat.md). It searches with the recorded vectors and asks `RONOTE_EMBED_URL` for the model's own tool queries. Per category it prints citation validity, section hit rate (an answerable query citing a block under the same headings as an expected one) and strict hit rate (citing an expected block itself), false and correct refusals (the model called `not_in_library`), unsourced answers (text, no citation) and self-written citation markers, time to first token and in all at p50 and p95, and mean cost; then writes `testdata/retrieval/chat-report.md` and every answer, with its citations, status, tool rounds, usage and cost, to `chat-answers.jsonl`, from Anthropic's API only. `RONOTE_EVAL_CHAT_URL` points it at the fake model for a dry run that writes nothing. `ids=e06,n04` asks only those questions, `repeat=N` times each, and prints each answer (a part, so no report); `limit=N` asks only the first N questions, and `budget=` (dollars, default 1.50) stops before the next question once the answers have cost that much; each answer prints its cost and the running total, and a part of the questions writes no report but projects what all would cost. Targets marked (P0x) do not exist yet. The phase that adds a target removes its tag.

Web targets, `make lint` and `make test` check that `node --version` matches `.nvmrc` first; with nvm, `nvm install && nvm use` picks it up.

Go CLIs are pinned as `tool` directives in go.mod (`go get -tool`) and run with `go tool <name>`: deadcode, goose, sqlc, river, oapi-codegen. golangci-lint is the exception: `make tools` installs the version pinned in the Makefile into `./bin`.

The API is spec-first: change `api/openapi.yaml`, then `make generate`. Never hand-write a type the spec defines: Go uses `internal/httpapi/gen`, TypeScript imports from `apps/web/src/api/schema.d.ts`, and a Vitest test fails on a TypeScript copy of a spec type. Error codes are enums in the spec (`ErrorCode`, `ImportErrorCode`), so Go uses the generated constants. The spec's IR schema maps onto `internal/ir` (`x-go-type`), and `TestIRSchemaMatchesGoldens` keeps the two in step.
