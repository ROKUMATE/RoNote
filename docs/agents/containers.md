# Local containers and running locally

The local stack: containers, the dev environment, and the processes dev runs.

## Local containers

- macOS uses podman machine (rootless); Linux and CI use Docker. `scripts/container.sh` picks whichever answers.
- `podman compose` needs a compose provider: `brew install docker-compose` (or podman-compose). `make dev-up` fails with a clear message when neither `podman compose` nor `docker compose` works.
- After the Mac sleeps, podman machine's clock can lag the host's for minutes. Postgres then writes times on the VM's clock while the app uses the host's; River copes since P12 (ADR 0005), but a test that compares the two still fails. Run `make doctor` when integration tests fail oddly.
- The end-to-end tests have a stack of their own, never the dev one: `make e2e-stack-up` runs the same compose file as project `ronote-e2e`, its host ports from `RONOTE_PG_PORT` and `RONOTE_S3_PORT` (55432 and 58333; the dev stack's default to 5432 and 8333), and `make web-e2e` starts it. `make e2e-stack-down` removes that project and its volumes, and nothing of `ronote`'s.
- `make dev-up` runs Postgres and SeaweedFS, the S3-compatible store uploaded PDFs go to (`127.0.0.1:8333`); SeaweedFS's healthcheck makes the `ronote` bucket, so `--wait` returns once it exists. The api and the worker check the bucket exists and takes a write as they start (`check-config` too, unless `--offline`), so neither starts without the store. `make dev-up-docling` adds the real docling and pdftext (`127.0.0.1:5001`, `:5002`): a 5 GB image wanting 6 GB of memory (`podman machine set --memory 8192`), on an internal network with no egress that only `converters-gate`, a socat forwarder, reaches (docs/adr/0013-pdf-import.md).
- `.env.example` lists every variable. Copy it to `.env.dev` (gitignored); the Makefile loads it, its values override the shell environment, and `make VAR=value` still wins.

## Running locally

Dev runs two processes, each in its own terminal, after `make dev-up` and `make migrate-up`:
- `make run-api` serves the API. Every `/api/v1` route but sign-in answers 401 without a session: sign in at `/login` through the fake GitHub (`cmd/fakeidp`), which `make web-dev` starts (or `make run-idp` alone). `.env.example`'s provider URLs point at it, and its users (`deploy/fakeidp/dev-users.json`) include `dev@ronote.local`, so documents from before sign-in stay reachable (docs/adr/0010-sign-in-and-sessions.md).
- `make run-worker` runs imports. Without it, imports stay `queued`.
- Chat answers from the fake model (`cmd/fakellm`), which `make web-dev` starts (or `make run-llm` alone), as `.env.example`'s `RONOTE_CHAT_URL` says. For the real model, set `RONOTE_CHAT_URL=https://api.anthropic.com` and `RONOTE_ANTHROPIC_API_KEY` in `.env.dev`; each question then costs a fraction of a cent (docs/adr/0012-chat.md).

- PDFs convert through the fake docling and pdftext (`cmd/fakedocling`), which `make web-dev` starts (or `make run-docling` alone): it replays the answers recorded for the fixtures in `testdata/pdf` and answers 503 to any other PDF. For any PDF of your own, stop it and run `make dev-up-docling`; both use the same addresses and keys.

docs/adr/0005-import-pipeline.md describes the pipeline both serve.

## The production units (docs/adr/0014-production-topology.md)

- `deploy/quadlet/` holds the Quadlet units, `deploy/caddy/Caddyfile` the front door (the app's site; `runner.caddy`, generated from `apps/web/runner-headers.ts`, is the runner's, which only CI and `make prod-local` serve, since production's is on Cloudflare Pages), `deploy/images/` the Containerfiles. `deploy/install.sh`, as root, makes the `ronote` user (rootless, lingering), lets it bind 80 and 443, installs the units, makes the podman secrets (never printed; kept across runs), pulls the embedding model, then restarts everything and returns once each unit is healthy; if one isn't, `deploy/report-failed.sh` prints for each unit that is down its status, journal, container log, health record and one health check run by hand, since systemd itself says only that it timed out. It refuses a Podman before 5.0 (Quadlet's `Entrypoint=`), and stops when Quadlet made no service for a unit, printing Quadlet's dry run, the Podman and systemd versions, the user generators, `ronote`'s systemd environment and the generator's log. First it checks that `ronote`'s systemd has its own directories (`deploy/check-environment.sh`: `XDG_RUNTIME_DIR` is `/run/user/<uid>`, the other `XDG_*_HOME` unset or in its home) and refuses otherwise, never overriding them: a host that trips it has another user's variables in `/etc/environment` or `/etc/security/pam_env.conf` (GitHub's runner image sets its own user's), to remove there before `systemctl restart user@<uid>.service`. `deploy/units.sh` writes the unit set, for it and `make units-check`. `sudo sh deploy/as-ronote.sh CMD` runs `systemctl --user`, `podman` or `journalctl --user` as that user.
- `deploy/bootstrap.sh --deploy-key FILE -- INSTALL-ARGS`, as root on Ubuntu 26.04 alone, prepares a fresh host and then runs `install.sh`: Podman, pasta and the scripts' tools with unattended upgrades on; upstream's rule letting podman signal pasta, added to Ubuntu's AppArmor profile for pasta and that profile reloaded, unless it or pasta's abstractions allow it already (`deploy/pasta-apparmor.sh`); a 2 GiB swap file with swappiness 10 where the host has no swap (`deploy/host-swap.sh`); sshd by key alone with no root login (skipped where there is no sshd, as on CI's runner); 80 and 443 opened before the REJECT that ends Oracle's `/etc/iptables/rules.v4` (`deploy/open-web-ports.sh`); the deploy user, whose key's forced command is `sudo -n /usr/local/bin/ronote-deploy "$SSH_ORIGINAL_COMMAND"` and whose one sudoers line allows that; and ronote-deploy's bare clone in `/opt/ronote/repo.git`. A second run changes nothing. `make prod-ci` installs through it.
- Deploys (docs/adr/0015-operations.md): `deploy/ronote-deploy.sh TAG`, as root, takes the tag's `deploy/` from a bare clone by `git archive` into a directory of its own, pulls the three images and pins them by digest (`install.sh --pin`, through `units.sh`), migrates and checks `api migrate status`, installs that release's units, and needs `/healthz` to name the tag; it records the digests in `/var/lib/ronote/deploy/current`, keeping `previous`, and on any failure reinstalls the previous release and alerts.
- Backups (docs/adr/0015-operations.md): `deploy/backup/` holds `backup.sh` (`db` nightly: `pg_dump -Fc` and each table's rows, counted from the dump; `pdfs` weekly: an rclone mirror of the bucket), `restore-drill.sh` (weekly: the newest dump into a scratch Postgres, `api migrate status`, the row counts compared, `api search-check`), their user services and timers, and the pinned restic and rclone images. `install.sh` installs them as `ronote`'s, with the secrets `ronote-restic-password`, `ronote-backup-repo` and `ronote-backup-access-key`/`-secret-key` from `RONOTE_RESTIC_PASSWORD`, `RONOTE_BACKUP_REPO` and `RONOTE_BACKUP_ACCESS_KEY`/`_SECRET_KEY`. No secret passes through the scripts: podman hands them to restic and rclone, whose containers run with `--log-driver=none`. `make backup-now` and `make restore-drill` (`deploy/run-now.sh`) run the same units now and print what they said; CI and `make prod-local` back up into a local repository and run the drill after the smoke suite.
- Alerts (docs/adr/0015-operations.md): `deploy/alerts/alert.sh` posts to `$RONOTE_NTFY_URL/<topic>`, the topic being the podman secret `ronote-ntfy-topic` (from `RONOTE_NTFY_TOPIC`), which never reaches a command line: curl reads it on stdin. A failed backup or drill starts `ronote-alert@`; `watch.sh`, every 5 minutes, alerts on a disk over 80%, a unit down or unhealthy for 5 minutes, the app's certificate within 14 days of expiring, and the api's `chat spend cap reached` line, each once a day while it lasts. Without `RONOTE_NTFY_URL` (CI), alerts only say what they would send. `install.sh` caps journald at 1 GB. `make watch-now` runs the watch now.
- `deploy/quadlet/ci/` sets `RONOTE_ENV=test`, no pulls and short start timeouts by drop-ins, and adds the fake sign-in, the fake model and SeaweedFS; a layer goes over it: `ci-fakes` swaps in the fakes for Ollama, docling and pdftext (CI's smoke jobs, `make prod-local`), or `real` keeps their real images (`make prod-real`, the weekly `arm-real` job). `install.sh --drop-ins` takes them in order, a later directory's files replacing an earlier's. Quadlet applies drop-ins by file name, whichever directory they are in, so the real layer's files sort after `start.conf`: `make units-check` checks both sets' effect.
- `make prod-local` installs them in the podman machine's VM (Fedora CoreOS: systemd, Quadlet, rootless podman), beside the dev stack's rootful containers, then runs the smoke suite from the Mac: an ssh tunnel from `127.0.0.1:8443` to the VM's 443 (macOS lets a user bind 443 only on every address), and Chromium maps `*.test` to it and trusts Caddy's CA by its key. The port check there looks at what the `ronote` user listens on, since the dev stack's own ports answer in the same VM. To look around: `podman machine ssh`, then `sudo sh /var/tmp/ronote/deploy/as-ronote.sh podman ps`.
- The VM's disk is 19 GB, docling's image 5 GB of it; the images build with cache mounts, so they don't hold Go's module cache.
